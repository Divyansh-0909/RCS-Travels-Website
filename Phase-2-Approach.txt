X 1. services/fare.js — Start here
This is the simplest piece and everything else depends on it. It takes pickup/drop addresses and vehicle type, then returns a fare.

The logic has two paths:

Fixed table lookup — query fare_table in the DB by destination name + vehicle type. Used for known NCR routes (Gurgaon, Noida, Airport, etc.)
Per-km fallback — if the destination isn't in the table, call Google Routes API, get distance in km, multiply by your per-km rate.
  - Checks api_usage table before every call — rejects with 503 if monthly count >= 10,000
  - Tolls are NOT included in the fare. Customer pays tolls directly to the driver.
  - Show "Tolls payable to driver separately" on frontend for per-km routes.
Output: { fare, distanceKm, fareSource }   ← no tollCharges, no baseFare

X 2. routes/fare.js — One endpoint
Just wires POST /api/fare/estimate to the service above. No auth required — the customer needs to see the fare before logging in.

X 3. services/driverAssignment.js — The core logic
This is the most complex piece. It takes a bookingId and finds the best available driver:

x Pull the booking's pickup coordinates
x Query driver_locations joined with drivers — filter for is_online = true, is_active = true, verificationStatus = 'approved'
x Sort by Haversine distance from pickup point
x If a tie then use the earliest join date to resolve
x Take the nearest driver, call notification.js to send them an FCM push (stubbed for now — just console.log)
x Record the attempt timestamp on the booking
x Wait 30 seconds — if no accept, move to the next driver and repeat
x If the list is exhausted: on-spot → return null (caller handles 503); scheduled → send WhatsApp alert to admin (stubbed) and leave booking as confirmed
x The retry loop is the tricky part. A clean way to handle it is a recursive async function with a setTimeout for the 30-second wait, iterating through the sorted driver list.

X 4. services/notification.js — Stubs only for now
Two functions: sendFCM(driverFcmToken, payload) and sendWhatsApp(phone, message). Both just console.log for Phase 2. You'll plug in real Firebase and Meta API in Phase 6. Keeping them as stubs means the rest of the code is already wired correctly.

X 5. routes/bookings.js — Three endpoints
POST /api/bookings (protected — Clerk JWT required):

x Validate inputs
x If scheduledAt is set and less than 30 minutes away → 422
x If scheduledAt is set and more than 30 minutes away → create booking with status = confirmed, set confirmedAt = now, return booking code
x If scheduledAt is null → create booking with status = pending, immediately call driverAssignment.js, if no driver found → delete the booking and return 503
x GET /api/bookings/:id/status (protected):

x Fetch booking by ID, verify it belongs to the requesting user
x Return status + driver info (name, phone, vehicle, current location + bearing + speedKmh) if assigned

6. routes/driver.js — Two endpoints (protected, driver JWT)
PATCH /api/driver/rides/:id/accept:

Set booking.status = assigned, booking.driverId = driver.id
Cancel the 30-second retry timer for this booking
PATCH /api/driver/rides/:id/decline:

Log the decline, trigger driverAssignment.js again to try the next driver

7. jobs/assignScheduledRides.js — Background job
A setInterval that fires every 5 minutes. Queries for bookings where status = confirmed AND scheduledAt <= now + 60 minutes (or now + 3 hours for outstation). For each match, calls driverAssignment.js. This job starts when the Express server starts.

How it all connects

POST /api/bookings
    │
    ├─ scheduledAt set (>2h) ──→ status = confirmed, job picks it up later
    │
    └─ scheduledAt null ───────→ driverAssignment.js runs now
                                      │
                                      ├─ driver found ──→ FCM stub → wait 30s
                                      │                        │
                                      │                   accept → status = assigned
                                      │                   decline → try next driver
                                      │
                                      └─ no drivers ──→ 503, booking deleted
