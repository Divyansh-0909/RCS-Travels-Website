## 1. Actual source mappings beyond a first FK path

It follows the union of all reviewed child paths to a fixed point, rather than selecting one path and discarding alternatives. Composite joins preserve all column pairs; NULL joins are not manufactured into matches. Identifiers are quoted, root IDs bound, row hashes computed on the server, and an exceeded bound fails instead of returning a truncated manifest. Returned IDs/object paths are sensitive metadata intended for protected handling, not public logs.

Current rows, archived file references and profile object references are collected without pulling unrelated parent drivers/users into a booking scope.

**23/23 persisted PostgreSQL checks pass.** The fixture contains all current table/column names as minimal text projections, using the saved FK graph, plus synthetic rows. It is not a full application schema/constraint/PostGIS restore and does not assert that an intentionally inconsistent projection can occur under product constraints. Tests cover alternate paths, the composite appeal/case binding, driver/vehicle versus driver-owned documents, archive objects, no parent sweep, stable commitments, missing roots, limits and isolation refusal. ## 2. Authenticated proprietor holds and existing local guards

The new optional [retention_registry.sql](../../tools/backups/retention_registry.sql) stores scopes, immutable copy bindings, observations, declared inventory commitments, overlapping holds, decision arguments/receipts and authenticated actor audit records. It has no application migration, automatic installation, deletion function or production deletion switch. PUBLIC table/sequence/function access is revoked. The fixture explicitly grants selected functions to distinct synthetic SQL logins; no Clerk role or real proprietor login is inferred.

Proprietor-only decisions check **session_user against the configured proprietor login**. An operator with even a test EXECUTE grant cannot place/release holds. Placement/release requires a unique operation, particular hold ID, expected epoch, approval reference and document hash. Exact operation reuse returns its stored operation receipt; it does not apply a new state transition or substitute for querying current hold status.

All active holds are counted: releasing one leaves other holds active. Final release reports RELEASED_REVIEW_REQUIRED. New copy identities invalidate the declared inventory; changing an existing identity's binding is rejected. Purged-copy observations require manual review. The optional local bridge atomically updates **already-enrolled** `retention9d.resources` and fences in-progress coordinator operations, allowing the existing retained-row guard to block held cleanup and tombstoned payload restoration. It does not enroll production records or promise a global remote hold barrier.

## 3. Provider inventory adapters and concrete capability limits

[retention_provider_inventory.py](../../tools/backups/retention_provider_inventory.py) adds read-only request adapters with explicit opt-in and bounded pagination. Remote use is disabled by default; no credential discovery, dotenv read, upload, object deletion, hold removal or lifecycle configuration is introduced.

- GCS inventory requests object generations and soft-deleted generations separately, preserving pagination and metadata revision/hold state. Unknown soft-delete configuration, missing generation bindings, duplicate generations, foreign-prefix objects and limits fail closed. Physical generation identity is distinct from mutable metadata observation identity, so setting a hold does not become a false content-identity conflict. Google documents the separate list options and restrictions; listing is not an atomic snapshot. [GCS list API](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/list)
- GCS object holds are actual provider controls with bucket compatibility and release effects; observing metadata does not place a hold. No live hold was set or released. [GCS object holds](https://docs.cloud.google.com/storage/docs/object-holds)
- R2 inventory uses the existing boto3 S3 LIST/HEAD interface for encrypted `.tar.age` generations; it does not count latest.json as another backup. Metadata checksums/ETags are not ciphertext readback proof. R2 S3 versioning/Object Lock APIs are not assumed; Cloudflare bucket-lock configuration is a separate capability and must be verified. [R2 S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/), [R2 bucket locks](https://developers.cloudflare.com/r2/buckets/bucket-locks/)

Provider request tests are **offline fixtures**, not actual Google account verification. R2 adapter protocol requests additionally run against a local Moto endpoint in the encrypted-backup test below.
