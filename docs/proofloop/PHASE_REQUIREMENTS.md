## Current test benefit and limits

Restoring the six exact baselines removes the documented historical-input availability block from the cloud baseline helper. It enables the local `baseline.mjs` and matrix/progress consumers to compare accepted identities, recover historical coverage rows and retain the exact readiness criteria. The accepted Clerk, V5 and custody identities were checked against both local and cloud source bytes during migration preparation; [source-baseline-verification.json](source-baseline-verification.json) records those checks.

Dependent saved recipes, fake-provider histories, snapshots, expected financial observations, raw mutation reports and exact source manifests support replay and retrospective interpretation. Restore them according to the index; a manifest whose payload is still private, absent or external is not a fully portable proof package. No failed test is repaired by moving a file, no source drift is waived, and migration does not complete current SQL/capsule/operational gates.

The cloud report's fresh receipts have different epochs and remain separately authoritative for their actual executions. Missing cloud-only output requires an export from that cloud workspace if it is to survive workspace loss. Fetching its Git commit retrieves source and documentation only.
